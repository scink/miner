# GitHub Pages и Telegram Mini App — спецификация

## Цель

Опубликовать игру как общедоступный статический сайт GitHub Pages и подготовить её к удобному запуску внутри Telegram Mini App без пользователей, авторизации и backend. Игра должна по-прежнему полноценно работать в обычном браузере.

## Границы задачи

В задачу входят:

- автоматическая сборка и публикация `dist` в GitHub Pages из ветки `master`;
- отдельный CI workflow с проверкой типов, тестами и production-сборкой на каждый push и pull request;
- корректные пути Vite для project Pages URL `https://scink.github.io/miner/`;
- тонкая интеграция с официальным Telegram WebApp SDK;
- адаптация высоты и безопасных областей под Telegram WebView;
- трёхрежимная тема `Система → Светлая → Тёмная`;
- документация по опубликованному URL и последующему подключению через BotFather.

В задачу не входят:

- Telegram-пользователи, `initData`, авторизация и серверная валидация;
- backend, база данных, таблица результатов и синхронизация между устройствами;
- платежи, сообщения боту и Telegram Main Button;
- создание или настройка бота в BotFather на этом этапе;
- PWA, service worker и офлайн-кэш;
- добавление ESLint или другого линтера, поскольку в проекте его сейчас нет;
- автоматическое изменение видимости GitHub-репозитория.

GitHub Pages-сайт должен быть публичным. Репозиторий остаётся с текущей видимостью. Если тариф GitHub не позволяет Pages для приватного репозитория, работа останавливается с понятным сообщением пользователю; репозиторий не переводится в public автоматически.

## Архитектура

### Сборка и GitHub Pages

Vite получает production base path `/miner/`, соответствующий project Pages URL. Локальный dev-сервер продолжает работать от `/`, чтобы существующие команды разработки не менялись.

Workflow `.github/workflows/pages.yml`:

- запускается при push в `master` и вручную через `workflow_dispatch`;
- устанавливает Node.js 24;
- использует `npm ci` и `npm run build`;
- загружает только каталог `dist` через официальный Pages artifact action;
- публикует artifact через официальный Pages deploy action;
- использует permissions `contents: read`, `pages: write`, `id-token: write`;
- использует environment `github-pages` и concurrency, отменяющий устаревший незавершённый deployment.

После merge Pages включается через GitHub API с источником GitHub Actions. Агент дожидается завершения deployment, проверяет итоговый URL и загрузку страницы.

### Continuous Integration

Отдельный workflow `.github/workflows/ci.yml` запускается:

- на каждый push во все ветки;
- на каждый pull request.

Он выполняет чистую установку зависимостей и команды:

1. `npm run typecheck`;
2. `npm test`;
3. `npm run build`.

Проверки линтера нет: отдельный линтер в рамках этой задачи не добавляется.

### Telegram-адаптер

В `index.html` подключается официальный Telegram WebApp SDK до основного module entrypoint. Небольшой модуль-адаптер изолирует обращения к `window.Telegram.WebApp` и предоставляет приложению только необходимые возможности:

- определить, действительно ли страница запущена внутри Telegram;
- получить текущую цветовую схему Telegram;
- подписаться на событие `themeChanged`;
- вызвать `ready()` после построения основного UI;
- вызвать `expand()` для максимальной доступной высоты.

В обычном браузере адаптер работает как безопасный no-op. Отсутствующий, частично доступный или более старый Telegram API не должен мешать запуску игры.

Принудительный fullscreen и блокировка вертикальных Telegram-жестов не используются: Mini App раскрывается через `expand()`, но сохраняет стандартный и предсказуемый способ выхода.

### Viewport и safe area

Layout использует динамическую высоту viewport и Telegram CSS variables, когда они доступны, с браузерными fallback через `100dvh` и `env(safe-area-inset-*)`.

Контент игры не должен попадать под верхние или нижние элементы Telegram и вырезы экрана. При этом существующая прокрутка больших игровых полей и модальных окон сохраняется. Изменения не должны добавлять фиксированную пиксельную высоту игровому окну.

## Тема

Тип предпочтения темы: `system | light | dark`. Значение хранится в `localStorage` под существующим ключом `minesweeper-theme`. Отсутствующее или неизвестное значение трактуется как `system`.

Пункт меню последовательно меняет режим:

1. `Тема: система`;
2. `Тема: светлая`;
3. `Тема: тёмная`;
4. снова `Тема: система`.

Текст пункта всегда показывает выбранный режим, а не только фактически применённую светлую или тёмную палитру.

Эффективная тема определяется так:

- `light` всегда применяет светлую палитру;
- `dark` всегда применяет тёмную палитру;
- `system` внутри Telegram использует валидное значение `Telegram.WebApp.colorScheme`;
- `system` вне Telegram использует `window.matchMedia('(prefers-color-scheme: dark)')`.

Если Telegram присутствует, но не сообщает валидную цветовую схему, используется браузерный media query; если недоступен и он — светлая тема.

В режиме `system` приложение без перезагрузки реагирует на `themeChanged` Telegram и на изменение браузерного media query. В ручных режимах системные события не переопределяют выбор пользователя.

## Инициализация

Последовательность запуска:

1. загрузить Telegram SDK;
2. создать безопасный Telegram-адаптер;
3. определить сохранённый режим темы и применить эффективную тему до или во время построения UI без заметного мигания;
4. построить игру и зарегистрировать обработчики темы;
5. после готовности основного интерфейса вызвать `ready()` и `expand()` при наличии Telegram API.

Ошибки доступа к `localStorage`, `matchMedia` или Telegram API не должны останавливать игру. Fallback — светлая тема и обычный браузерный layout.

## Тестирование

Автоматические тесты должны покрывать:

- цикл `system → light → dark → system` и подписи меню;
- default `system` для отсутствующего и неизвестного сохранённого значения;
- приоритет ручной темы над системной;
- выбор Telegram theme в режиме `system` внутри Mini App и browser fallback при неизвестной Telegram theme;
- выбор `prefers-color-scheme` в режиме `system` вне Telegram;
- реакцию на изменения Telegram и browser theme только в режиме `system`;
- безопасный no-op Telegram-адаптера в обычном браузере;
- вызовы `ready()` и `expand()` после инициализации UI;
- наличие корректного Vite base path;
- структуру CI и Pages workflows, их triggers, permissions и команды;
- сохранение существующего поведения игры, touch-управления, паузы, зума и модальных окон.

Финальная локальная проверка:

```bash
npm run typecheck
npm test
npm run build
git diff --check
```

После публикации дополнительно проверяются успешные GitHub Actions runs и HTTP-загрузка `https://scink.github.io/miner/`.

## Документация и передача

README получает:

- публичный URL игры;
- описание трёх режимов темы;
- пояснение поведения в Telegram и обычном браузере;
- короткие будущие шаги BotFather: создать бота, назначить опубликованный HTTPS URL как Main Mini App или Menu Button и проверить запуск на мобильном Telegram.

Bot token в репозиторий, workflow или клиентский код не добавляется.

## Критерии готовности

- каждый push и pull request запускает зелёный CI с typecheck, тестами и сборкой;
- push в `master` запускает успешный Pages deployment;
- публичный Pages URL загружает игру без 404 для JS/CSS assets;
- игра работает в обычном браузере и внутри Telegram WebView;
- Telegram получает `ready()` и Mini App раскрывается через `expand()`;
- контент учитывает safe area и остаётся прокручиваемым;
- тема корректно циклируется, сохраняется и обновляется от Telegram/ОС в режиме `system`;
- никакая секретная или пользовательская информация не требуется и не сохраняется.
